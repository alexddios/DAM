## ⚛️ 3. ¿Por qué React? (Del conocimiento previo al nuevo)
- **JavaScript:** Ya lo conocemos de 1º.
- **Componentes:** Construimos piezas pequeñas.
- **Composición:** Las piezas forman interfaces completas.
- **Reutilización:** Escribimos una vez, reutilizamos en múltiples lugares.
> **Idea central:** No queremos memorizar React, queremos entender su modelo mental.

## 🧠 4. Idea Importante: React no es React Native
El modelo mental es el mismo, pero el destino cambia:
- **React (Core):** Componentes, props, estado, hooks.
  - ⬇️ **React DOM:** Interfaces web (Navegador).
  - ⬇️ **React Native:** Interfaces móviles (Android + iOS).
*Primero entenderemos React. Después llevaremos el mismo modelo al móvil.*

## 🧩 8. JSX (JavaScript XML)

Parece HTML... pero no lo es. Nos permite describir la interfaz visual directamente dentro de JavaScript.

- Las llaves `{ ... }` permiten introducir expresiones de JavaScript dinámicas.
```js
const nom = "Miquel";

function App() {
  return (
    <div>
      <h1>Hola, {nom}!</h1>
    </div>
  );
}
```
## 🧱 9. La idea clave de React: El Componente
Un componente es simplemente una función que devuelve una porción de interfaz. Nos permite crear nuestras propias etiquetas reutilizables.
```js
function StudentCard() {
  return (
    <div>
      <h2>Miquel</h2>
      <p>2n DAM</p>
    </div>
  );
}
```
**Uso:** Al crear este componente, ahora podemos usar la etiqueta `<StudentCard />` todas las veces que queramos, creando instancias independientes.

## 📥 10. Props: Mismo componente, datos diferentes
- Las `props` permiten usar la misma estructura visual de un componente pero alimentándolo con datos distintos.
- Esto se define pasando parámetros a la función del componente.
- Código de ejemplo de la definición:
  ```jsx
  function StudentCard({ nom, curs }) {
    return (
      <div>
        <h2>{nom}</h2>
        <p>{curs}</p>
      </div>
    );
  }
  ```
  - Código de ejemplo de su uso:
```js
<StudentCard curs="2n DAM" nom="Maria"/>
<StudentCard curs="2n DAM" nom="Joan"/>
<StudentCard curs="1r DAM" nom="Pere"/>
```
## 🧩 11. Composición: Componentes dentro de componentes

- La composición en React se basa en colocar componentes dentro de otros componentes de jerarquía superior .
    
- Una interfaz grande es siempre el resultado de componer piezas más pequeñas .
    
- Estructura conceptual de ejemplo mostrada :
    
    - Un componente principal `App` que engloba a otros .
        
    - Dentro de `App` se ubican los componentes `Header`, `GameList` y `Footer` .
        
    - A su vez, el componente `GameList` contiene en su interior varias instancias del componente `GameCard` .
## 🔄 12. Estado: Cuando la interfaz puede cambiar
- El estado es información que puede cambiar mientras la aplicación se ejecuta.
- Un evento provocado por una acción del usuario puede modificar este estado.
- Al cambiar el estado, React renderiza de nuevo y actualiza la interfaz visual.
- Para gestionar el estado se utiliza el hook `useState` de React.
- Código de ejemplo con un contador:
  ```jsx
  import { useState } from "react";
  
  function Counter() {
    const [count, setCount] = useState(0);
  
    return (
      <button onClick={() => setCount(count + 1)}>
        Clics: {count}
      </button>
    );
  }
  ```
## 🔀 13. Eventos y renderizado condicional

- Las interacciones del usuario (como un clic) disparan acciones mediante eventos como `onClick`.
    
- El resultado de esa acción se guarda utilizando el estado.
    
- Se utiliza una condición para que la interfaz de usuario muestre una cosa u otra en base a ese estado.
    
- Ejemplo de sintaxis de renderizado condicional con operador ternario:
```jsx
{favorit ? (
  <p>♥ És favorit</p>
) : (
  <p>♡ No és favorit</p>
)}
```
## 📋 14. Listas: De los datos a los componentes

- Se parte de unos datos de origen, normalmente estructurados como un array de objetos.
    
- Se emplea la función `.map()` de JavaScript para transformar cada elemento del array.
    
- El objetivo del mapeo es convertir cada objeto de datos en una pieza o componente de la interfaz.
    
- Cada componente renderizado dentro de la lista requiere de una propiedad única `key` asociada a un identificador.
## 📱 15. El salto a React Native

- Al pasar a React Native el modelo mental de desarrollo no cambia, pero dejamos de programar para web.
    
- React sigue siendo React, pero se modifica la plataforma destino donde se renderiza la aplicación.
    
- Equivalencias fundamentales de las etiquetas HTML a componentes nativos:
    
    - `<div>` se sustituye por `<View>`.
        
    - `<p>` o `<span>` se sustituyen por `<Text>`.
        
    - `<img>` se sustituye por `<Image>`.
        
    - `<button>` se sustituye por `<Pressable>`.
        
    - `CSS` se sustituye por el sistema de `styles` de React Native.
        

## 🛠️ 16. React Native y Expo

- React Native consiste en aplicar los componentes y el modelo de React a las interfaces nativas móviles.
    
- Se utiliza una misma base de código compartida para las plataformas Android e iOS, aunque pueden requerir adaptaciones.
    
- Se advierte que ser multiplataforma no significa que el código funcione por "magia" en ambos sistemas sin ajustes.
    
- Expo se utiliza para simplificar el proyecto, facilitar el desarrollo y acceder a múltiples APIs del sistema.

## 📲 18. ¿Emulador o dispositivo real?

- A lo largo del curso se utilizarán ambos entornos de prueba.
    
- **Emulador:**
    
    - Ventajas: Es rápido para realizar pruebas, permite configurar distintos dispositivos y es fácil de reiniciar.
        
    - Inconvenientes: No siempre reproduce de forma exacta el comportamiento del hardware real.
        
- **Dispositivo real:**
    
    - Ventajas: Permite acceder a los sensores físicos, gestionar permisos reales y comprobar el rendimiento auténtico.
        
    - Inconvenientes: Requiere instalar más dependencias y procesos de configuración.
        

## ⚖️️ 19. Android e iOS: Multiplataforma ≠ Idéntico

- Parte fundamental del desarrollo multiplataforma es aprender a detectar y gestionar las diferencias entre los sistemas operativos.
    
- **Permisos:** No se declaran ni se solicitan siempre de la misma forma en Android que en iOS.
    
- **Hardware:** Las capacidades físicas varían dependiendo de los diferentes modelos de dispositivos.
    
- **APIs:** Existen funcionalidades que son específicas de una plataforma.
    
- **UI y comportamiento:** Pueden surgir variaciones en la interfaz visual y la interacción entre sistemas.
